## Notification Workers Run on PostgreSQL (Supabase)

Since 2026-10-31 both production Workers use PostgreSQL through the `DB` Hyperdrive binding (`opencast-notifications-production`, caching off, `verify-full` against the Supabase root CA). The database is a free-tier Supabase project in Canada Central, reached through its session pooler. The old D1 database `opencast-notifications-db` was deleted on 2026-10-31.

- Roles: `opencast_owner` (schema owner, setup only), `opencast_runtime` (Hyperdrive), `opencast_reader` (read-only). Their URLs and passwords are in the git-ignored `Server/Toolbox/cloudflare.env`; the Supabase root CA is the git-ignored `Server/Toolbox/prod-ca-2021.crt`.
- Both git-ignored production configs pin `STORAGE_IDENTITY` to that database. A new database needs a new pin.
- The schema was applied once by hand in `Server/NotificationsWorker/postgres/README.md`'s single-runtime-role order. `deploy-production.sh` only checks it is there and opens the new-episode `n_control` rows. A schema change is a new migration applied by the owner.
- The APNs mTLS certificate must include Apple's WWDR G4 intermediate, or every send fails with an empty 500.
