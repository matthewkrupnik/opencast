## Do Not Deploy the Notification Workers

Do not run `Server/Toolbox/deploy-production.sh`, `wrangler deploy`, or any other deploy of NotificationsWorker or FeedPollingWorker, and do not add CI or hooks that deploy them, until the user says the PostgreSQL migration is done.

Upstream `62e2746` (merged 2026-10-19) moved both Workers' storage from D1 to PostgreSQL through a Hyperdrive binding named `DB`. The git-ignored `wrangler.production.toml` / `wrangler.production.jsonc` and `deploy-production.sh` still use D1, so deploying the current code with them refuses every storage call and stops new-episode push notifications. The live Workers keep running the pre-merge code until a redeploy.

Before deploying: provision PostgreSQL 16+, apply `Server/NotificationsWorker/postgres` in its single-runtime-role order, create the Hyperdrive config with the runtime role, set `STORAGE_AUTHORITY = "postgres"` and the `DB` binding in both production configs, and replace the D1 steps in `deploy-production.sh`.
